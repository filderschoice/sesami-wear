1. 概要と読み方

この文書の画像はすべて、実装コード(Compose / Glance / Wear Tiles / XML)から文言・寸法・色を転記してHTML/CSSで描いた「再現」です。実機のスクリーンショットではありません。例外は 4.4 の「ウィジェット一覧プレビュー」2枚で、これはリポジトリに入っている実画像です(ストア掲載用スクリーンショットの切り出し)。フォント・OS既定部品の細部・M3既定色はM3既定値からの再現で、実機との差は「未確認」です。サンプルの名前・数値は架空です(角度は実測の標準値: 施錠-180・解錠-270)。

3. スマホアプリの画面

3.1 主画面(デバイス一覧)

構成: 上部バー(タイトル「Sesami Wear」+ ⋮ 設定メニュー) / 縦スクロールのカード一覧 / 右下FAB「Sesameを追加」。未登録のときは登録を促す空状態のみ。この画面に施錠・解錠ボタンは無い(施錠・解錠はウィジェット・ウォッチ・クイック設定・ダイヤル操作)。一覧の表示のために状態取得の通信はしない(最後に分かった値を表示、画面再開のたびに読み直す)。

3.3 設定系ダイアログ

解錠したままの選択肢は SesameAlertSettingsStore.UNLOCK_REMINDER_CHOICES = [0, 5, 10, 30](0=オフ、既定オフ)。

Bluetooth権限ダイアログの状態本文(要旨)ボタン
NOT_REQUESTED(未許可)許可するとSesameの近くでは直接操作し、APIのリクエスト回数を消費しなくなる。許可しなくてもインターネット経由で動く「Bluetoothの利用を許可する」/「あとで」
DENIED(拒否済み)許可されていない。端末の設定から許可すると直接操作になる「端末の設定を開く」/「あとで」
GRANTED(許可済み)近くにあるときはBluetoothで直接操作、APIを消費しない(確認ボタン無し)/「あとで」

タイトルは「近くのSesameをBluetoothで操作する（任意）」。Android 12未満では「位置情報の許可が必要(収集・送信しない)」の注記が追加される。

4. ホーム画面ウィジェット(Glance)

2つのプロバイダ(4x2「Sesami Wear」/ 2x1「Sesami Wear（小）」)が同じ描画を使い、違いは初期サイズだけ。表示は配置サイズで3レイアウトに切り替わる。ライト/ダークは端末設定へ追随(背景・チップ・文字色)、状態色は固定。

レイアウト条件(dp)構成
FULL幅 ≥ 200 かつ 高さ ≥ 172左列(幅96)=「更新」「変更」チップ / 右=名前ヘッダ(経路アイコン+名前)+状態ボックス(絵文字28sp・状態16sp太字・詳細11sp・操作13sp)
MEDIUM幅 ≥ 110(FULL未満)左列(幅50–72)=名前チップ(タップで更新)+「◀」「▶」(対象切替)/ 右=状態ボックス(絵文字+状態名13sp、狭いと11sp)
COMPACT上記未満(最小40×40=1マス)状態ボックスのみ(絵文字24sp+状態名13sp)。未設定は「設定」

既定の4x2(250×110dp)は高さが172未満のためMEDIUMで描かれ、FULLになるのは縦に3マス程度まで広げたとき(SesameWidgetLayout.of の条件より算出。実機での見え方は未確認)。ストア掲載のプレビュー画像(4.4)はFULL。

4.1 FULL(幅250×高さ172)

4.2 MEDIUM(例: 150×56)/ COMPACT(64×64)/ 未設定

操作動作
状態の種類スマホのウィジェットは常に「スマホ接続あり」で解決するため、「スマホ未接続」は出ない(出るのはウォッチのTile・Complication)。施錠中/解錠中/一部解錠(全デバイス)/通信中/状態不明
右(状態ボックス)タップ施錠=即実行、解錠=確認画面(4.3)を挟む。通信中・状態不明はタップ無効。未設定=対象選択を開く
「更新」/ 名前チップ状態取得(1台=その台、全デバイス=全台)。通信を1回使う
「変更」(FULL)対象選択(WidgetConfigurationActivity)。「◀▶」(MEDIUM)は登録順に巡回(WidgetDeviceCycle)
アクセシビリティ状態ボックス=「{名前}、{状態}、{詳細}、電池残量{N}%、{操作}」(電池20%未満は「電池残量が少なくなっています N%」)。更新=「{名前}の状態を更新」、変更=「操作するSesameを変更」、◀=「前のSesameへ切り替え」、▶=「次のSesameへ切り替え」、未設定=「Sesami Wearのウィジェット。タップして操作するSesameを選びます」

6. ウォッチ(Wear OS)

ウォッチ画面はすべて黒背景・白文字(Wear既定テーマ)。状態色はスマホと共通(core定義)。再現は直径200pxの円で、実機の画面サイズ・曲面での見え方は未確認。

6.1 Tile

要素仕様
レイアウト外側余白16dp / 左列幅56(「更新」「変更」の2チップ、縦に等分) / 間隔6 / 右列(名前ヘッダ + 状態ボックス)。チップ: 角丸12・内余白6。名前ヘッダ: 角丸12・余白 横6・縦3、経路アイコン12 + 名前(CAPTION2・1行省略)
状態ボックス絵文字(DISPLAY2) / 状態名(TITLE2・最大2行) / 詳細(CAPTION3・1行) / 操作文(CAPTION2・最大2行)。背景=状態色、文字色=表の文字色。操作が無い状態(通信中・未接続・不明)はタップ無効
左列「更新」=状態取得(SesameStatusRefreshActivity)。「変更」=対象選択(TileConfigurationActivity)。色=灰チップ#424242・白文字
詳細文失敗があれば失敗理由の短縮形(「認証エラー」「通信エラー」)、無ければ鮮度(たった今/N分前/N時間前/M/D)。電池は「🔋85%」、20%未満は「⚠🔋18%」
アクセシビリティ状態=「{名前} {状態文言}」、更新=「{名前} タップして状態を更新」、名前=「{名前} 経路 {Bluetooth/インターネット}」
リソース経路アイコン(ic_route_bluetooth / ic_route_internet)を画像として登録(RESOURCES_VERSION=2)

6.2 解錠確認・送信中・対象選択・状態一覧

確認画面を挟むのは解錠のみ(SesameCommandConfirmation.isRequired = UNLOCK のとき)。施錠は確認なしで「送信中...」へ進む。

状態一覧の要素仕様
カード状態色背景・角丸12・内余白6。4行(名前CAPTION1 / 状態+電池BODY2 / 鮮度・経路CAPTION2 / 操作文CAPTION2)。タップ=コマンド実行(解錠は確認)または状態取得
フッターチップ1台=「更新」(灰)、2台以上=「全施錠」(緑)と「すべて更新」(灰)。0台=無し
経路状態一覧とComplicationでは絵文字(🔗=Bluetooth、🌐=インターネット)。Tile・スマホはベクタアイコン

10. 所見

根拠はコード・計算。実機で確認していないものは「未確認」。優先度付け・起票は含めない。

  1. 状態色の白文字コントラストが低い面がある(計算値)。白文字 on 緑 #4CAF50 = 2.78:1、on 灰 #9E9E9E = 2.68:1、on 赤 #F44336 = 3.68:1(WCAGの大きな文字の基準は3:1)。状態名は太字13–16spで「大きな文字」の定義(約18.7dp太字以上)には満たないため、小さな文字の基準4.5:1に対しては不足する。操作文・詳細は同背景の通常ウェイト11–13sp。実機での視認性は未確認。
  2. 施錠状態の絵文字はフォント依存。ウィジェット・Tile・状態一覧は🔒🔓🔀⏳📵❔をテキストで描く。スマホのカードバッジはベクタ(BL-245でフォント差を避けるため変更)。同じ状態でスマホ内でも2通りの表現が混在する。
  3. スマホ主画面に施錠・解錠の直接操作が無い。操作はウィジェット・クイック設定・ショートカット(全施錠のみ)・ウォッチ・ダイヤル操作に分かれ、ダイヤル操作はBluetooth限定で、インターネット経由の操作はアプリ画面からは行えない。意図(BL-243: 効かないときの手段)はコメントにあるが、利用者が「アプリを開いて鍵を回す」を期待した場合の導線は未確認。
  4. ウォッチ画面はブランド紺 #1E3A5F を使っていない。黒背景+状態色+灰チップのみ(Wear既定テーマ)。スマホはBL-245で紺に統一済み。ウォッチ側の意図は未確認。
  5. ウォッチTile・ウィジェットのニュートラル色は2系統。Tileは常にダーク相当、ウィジェットはライト/ダーク追随。(ウィジェットのダーク色はTileの定数を共有して揃えている。ライト色#D9D9D9等は別定義。)
  6. ヘルプの説明とウォッチTileの配置が食い違う。ヘルプ「登録後のウォッチでの使い方」は「タイル左下の『変更』」「タイル左上のデバイス名をタップすると最新の状態を取り直す」、「APIのリクエスト回数の上限」は「デバイス名をタップして状態を取り直したとき」と書くが、Tileの実装では名前ヘッダは操作不可で、状態取得は左列上段の「更新」チップ(左下は「変更」)。文言は HelpContent.kt、配置は SesameTileService.kt(コード確認済み。実機未確認)。
  7. 多言語未対応。文言は日本語直書きでstrings.xmlに無い(7件のみ)。表示文言を直すとき定義元が散らばる(core/display・各Composable・HelpContent)。
  8. 設定メニューの項目数が多い(最大8項目)。副題で現在状態を出す設計は意図的(BL-180)。項目の順序はコード順で、利用頻度との対応は未確認。
  9. ウィジェットの既定4x2は実際にはMEDIUM描画の可能性。既定サイズ250×110dpは高さ172dp未満。ストア掲載・プレビュー画像はFULLで、利用者が最初に見る形と一致するかは未確認。
  10. 通知の重要度が2チャンネルで異なる。経路変化=LOW(静かに出る)、お知らせ(電池・解錠したまま)=DEFAULT(音あり)。意図は未確認。
  11. アクセシビリティ文言は整備されている(ウィジェット・Tile・ダイヤルにcontentDescription)。一方、ウォッチ状態一覧のカードにはTile相当のcontentDescription指定が無い(コード確認済み。画面読み上げでの実際の読まれ方は未確認)。
  12. ダークテーマ対応は完了、動的カラーは意図的に不使用(状態色との競合回避、SesameThemeのコメント)。ダークのsurface等はM3既定値で、この文書の図はM3既定値からの再現。
