# リリースノート

Sesami Wear のバージョンごとの変更点を、アプリ利用者向けに記録します。
最新の配布状況やサポート窓口は [SUPPORT.md](SUPPORT.md) を参照してください。

## このファイルの位置づけ

| ファイル | 対象読者 | 記録する内容 |
| --- | --- | --- |
| 本ファイル（`docs/RELEASE_NOTES.md`） | アプリ利用者 | アプリのバージョンごとの新機能・改善・修正・既知の問題 |
| [CHANGELOG.md](../CHANGELOG.md) | 開発者・メンテナー | リポジトリの運用ルール・ドキュメント・ガードレールの変更履歴 |
| [docs/records/managed/EXECUTE.md](records/managed/EXECUTE.md) | 開発者・AIエージェント | コード修正1件ごとの実施記録（変更ファイル・検証結果を含む） |

利用者に影響する変更（機能追加、UIの変更、不具合修正）を行った場合は、本ファイルへ追記します。
内部リファクタリングやドキュメントのみの変更は追記不要です。

## 運用ルール

- 新しいバージョンを先頭に追加します（新着順）。
- 見出しは `## <バージョン>（<リリース日>）` の形式とします。未リリースのものは日付の代わりに
  「未リリース」と記載します。
- 各バージョンは「新機能」「改善」「修正」「既知の問題」の小見出しで整理します。該当がない項目は
  省略します。
- 記載は利用者が読んで分かる言葉で書きます（クラス名・タスクidなどの内部名称は使いません）。
- バージョン番号は `scripts/version.properties` の `VERSION_NAME` と一致させます。リリースビルドの
  手順は [README.md](../README.md)「リリースビルド・Google Play公開」を参照してください。
- Google Play Consoleの「このリリースの新機能」欄は500文字以内です。各バージョンの
  「ストア掲載用の要約」をそのまま転記できるよう用意します。
- GitHub Releasesを作成する場合も、本ファイルの該当バージョンの内容を本文へ転記します。

## 0.12.0（未リリース）

Sesame の Web API には1か月あたりのリクエスト回数の上限があり、本アプリの自動的な状態取得だけで
その上限を使い切ってしまうことが分かりました。上限に達すると、状態の取得も施錠・解錠もすべて
失敗します。これを避けるため、状態の取得を利用者の操作に限定しました。

### 新機能

- ホーム画面ウィジェットの**大きさを変えられる**ようにしました。ホーム画面の1マスまで小さくでき、
  小さいときは状態アイコンと状態文言だけの表示になります（タップしたときの動きは同じです）。
- ホーム画面ウィジェットから施錠・解錠したときに、**結果をスマートフォンの振動でも**お知らせする
  ようにしました。成功は短い振動2回、失敗は長い振動1回で、ウォッチのタイルと同じパターンです。

### 改善

- タイル・コンプリケーションを表示したときの**自動的な状態取得をやめました**。状態が更新されるのは、
  施錠・解錠が成功したときと、タイル・ホーム画面ウィジェットのデバイス名をタップしたときだけです。
- 代わりに、**その状態をいつ取得したかを表示する**ようにしました。「たった今」「3分前」「2時間前」の
  ように経過時間で表示し、24時間以上前のものは日付（「9/17」）、一度も取得していない場合は「未取得」と
  表示します。「全デバイス」を選んでいる場合は、最も古い取得時刻を表示します。
- 状態の取得や施錠・解錠に**失敗したときに、その理由を表示する**ようにしました。APIキーが
  受け付けられなかった場合は「認証エラー」（ウィジェットでは「認証エラー（設定を確認）」）、
  通信できなかった場合は「通信エラー」と表示します。これまでは失敗しても「状態不明」と出るだけで、
  設定を見直す手がかりがありませんでした。失敗してもそれまでに分かっていた施錠状態はそのまま残します。
- スマートフォンアプリの設定画面に、**今月のAPI呼び出し回数**を表示するようにしました。
  このアプリからの呼び出しだけを数えた目安で、他の経路で使った分は含みません。
- アプリの「ヘルプ」に「**APIのリクエスト回数の上限**」を追加しました。上限の存在と、上限に
  達したときの表示、当月の利用状況の確認先（SESAME Biz）、対処方法を記載しています。
  「値の取得方法」にはAPIキーの取得手順を説明したCANDY HOUSE公式の記事へのリンクを追加しました。
- デバイス名を連続してタップしたときに、**2秒以内の繰り返しを無視する**ようにしました。
  誤って二度押ししてもAPIのリクエストを余計に使いません（施錠・解錠は以前から同じ動作です）。
- 施錠・解錠や状態取得に失敗したときに、失敗の理由（通信エラーの種類）が端末のログへ残るように
  しました。お問い合わせいただいたときの原因調査に使います。記録されるのはエラーの種類だけで、
  APIキーや秘密鍵、Sesameの識別子は含みません。

### 既知の問題

- Sesame純正アプリや手動でロック状態を変えた場合、本アプリの表示は手動で更新するまで追随しません。
  デバイス名をタップして更新してください。

### ストア掲載用の要約（Google Play「このリリースの新機能」欄）

```text
・状態の自動取得をやめました
　SesameのWeb APIには月間のリクエスト上限があり、自動取得だけで使い切ってしまうためです
　上限に達すると、状態の取得も施錠／解錠もすべて失敗します
・状態が更新されるのは、施錠／解錠に成功したときと、デバイス名をタップしたときだけになりました
・状態をいつ取得したかを表示するようにしました（「3分前」「9/17」「未取得」など）
　表示が古いと感じたら、デバイス名をタップして更新してください
・取得や操作に失敗したときに、理由（認証エラー／通信エラー）を表示するようにしました
・「ヘルプ」に「APIのリクエスト回数の上限」を追加し、設定画面に今月のAPI呼び出し回数を
　表示するようにしました（このアプリからの分のみの目安です）
・ホーム画面ウィジェットの大きさを変えられるようにしました（1マスまで縮小できます）
・ウィジェットからの施錠／解錠の成否を、スマートフォンの振動でもお知らせするようにしました
```

## 0.11.0（2026-09-18）

スマートフォンのホーム画面から、ウォッチを使わずにSesameを操作できるようにしました。

### 新機能

- スマートフォンのホーム画面ウィジェットを追加しました。ウォッチのタイルと同じ表示で状態を確認でき、
  右側のタップで施錠（すぐに実行）・解錠（確認画面あり）を行えます。デバイス名のタップで状態を
  取り直し、「変更」で操作対象を選び直せます。
- ウィジェットごとに操作対象のSesameを選べます。2台以上登録している場合は「全デバイス」で一括操作できます。
- Sesameを登録していない状態では、ウィジェットでも「デモ」を選んで操作を試せます。
  ウォッチのデモとは連動せず、スマートフォンの中だけで状態が切り替わります。
- ウィジェットで操作するとウォッチのタイルが、ウォッチで操作するとウィジェットが追随して更新されます。

### 改善

- スマートフォンアプリの「ヘルプ」に「ホーム画面ウィジェットの使い方」を追加し、
  「Sesameが無くてもデモで試す」をウィジェットでの試し方も含む内容にしました。

### 修正

- スマートウォッチ用のアプリ（Pixel Watch アプリなど）が入っていないスマートフォンで、
  Sesameの登録・削除時にアプリが終了するおそれがあった問題を修正しました。
- 電波が届かない場所などSesameと通信できない状態でウィジェットを操作したときに、アプリが終了したり、
  ホーム画面に「ウィジェットが繰り返し停止しています」と表示されたりすることがあった問題を修正しました。
- ウィジェットの表示が「通信中...」のまま変わらなくなり、タップしても反応しなくなることがあった問題を
  修正しました。しばらく置くか、アプリを開き直すと現在の状態の表示へ戻ります。
- Sesameとの通信が終わらない場合に、一定時間で打ち切るようにしました。操作が長く待たされて、
  そのまま反応が返らなくなることを防げます。

### ストア掲載用の要約（Google Play「このリリースの新機能」欄）

```text
・スマートフォンのホーム画面ウィジェットを追加しました
　ウォッチが無くても、タイルと同じ表示・操作で施錠／解錠できます
・ウィジェットでも「デモ」で操作を試せます
・「ヘルプ」にウィジェットの使い方を追加しました
・通信できない場所でウィジェットを操作したときに、アプリが終了したり、表示が「通信中...」の
　まま戻らなくなったりすることがあった問題を修正しました
・ウォッチ用アプリが無いスマートフォンで、登録・削除時に終了するおそれがあった問題を修正しました
```

## 0.10.0（2026-09-14）

Sesameをまだ登録していない状態でも、アプリの操作感を確認できるようにしました。

### 新機能

- Sesameの資格情報をまだ登録していない場合、タイルとコンプリケーションの対象として
  「デモ」を選べるようになりました。実際の鍵は動かさず、施錠・解錠の操作、確認画面、
  振動での通知、文字盤への状態表示を一通り試せます。
- デモではスマートフォンとの通信を行わないため、スマートウォッチ単体で操作を確認できます。
- スマートフォン側にSesameを1台でも登録すると、デモの選択肢は表示されなくなり、
  登録したSesameのみが対象になります。

### 改善

- uuid・apikey・secretKeyの入力欄が半角文字のみを受け付けるようになりました。全角で入力・
  貼り付けした英数字は自動的に半角へ変換され、値として現れない文字は取り除かれます。
  全角文字の混入による操作の失敗を防げます。
- スマートフォンアプリの「ヘルプ」がメニュー形式になりました。従来の「値の取得方法」に加えて、
  「Sesameが無くてもデモで試す」「登録後のウォッチでの使い方」を選べます。Sesameを持っていない
  場合でも、デモの始め方をスマートフォン側から確認できます。

### ストア掲載用の要約（Google Play「このリリースの新機能」欄）

```text
・Sesame未登録でも試せる「デモ」を追加しました
　実際の鍵は動かさずに、施錠／解錠の操作、確認画面、振動での通知、
　文字盤への状態表示を一通り確認できます
・Sesameを登録するとデモの選択肢は表示されなくなります
・uuid／apikey／secretKeyの入力欄が半角文字のみを受け付けるようになりました
・アプリの「ヘルプ」をメニュー形式にし、デモの始め方と登録後の使い方を追加しました
```

## 0.9.0（2026-09-07）

初回リリースです。Google Playの内部テスト（限定公開）で配信しました。現在の配布状況は
[SUPPORT.md](SUPPORT.md)「現在の配布状況」を参照してください。

### 新機能

- スマートウォッチのタイルから、Sesameスマートロックの施錠・解錠を実行できます。
- 施錠はワンタップで即実行、解錠は確認画面を挟むことで誤操作を防ぎます。
- 操作の成否を、成功と失敗で異なる振動パターンで通知します。
- ウォッチフェイスのコンプリケーションへ、現在の施錠状態を表示できます。
- 複数台のSesameを登録し、タイルやコンプリケーションごとに操作対象を切り替えられます。
- 2台以上を登録している場合、「全デバイス」を選んで一括で施錠・解錠できます。施錠と解錠が
  混在している場合は専用の表示になり、タップすると全施錠を実行します。
- スマートフォンとの接続が切れている場合は、タイル上に「スマホ未接続」と表示して操作を止めます。

### 既知の問題

- 定期的な状態の問い合わせを行わないため、Sesame純正アプリなど他の経路で施錠状態が変わった場合、
  タイル・コンプリケーションの表示は次の更新まで反映されません。タイルのデバイス名部分をタップすると
  最新状態を取得できます。
- 同じタイルを2つ以上追加することが、ウォッチ側のタイル管理画面の制約でできません。1つのタイルで
  対象デバイスを切り替えて利用してください（コンプリケーションは枠ごとに別のデバイスを設定できます）。
- アプリを入れ直した直後に、コンプリケーションの枠へデバイスを割り当てても表示されないことが
  あります。ウォッチ側に古い設定状態が残ることが原因で、スマートウォッチを再起動してから割り当て
  直すと解消します（Wear OS側の事象です）。

### ストア掲載用の要約（Google Play「このリリースの新機能」欄）

```text
初回リリースです。
・タイルからワンタップで施錠、解錠は確認画面付きで誤操作を防止
・成功／失敗を振動パターンで通知
・ウォッチフェイスのコンプリケーションに施錠状態を表示
・複数台のSesameを登録し、タイルごとに対象を切り替え
・2台以上なら「全デバイス」で一括施錠／解錠
・スマートフォン未接続時はタイル上で明示
```
